## Дослідження 4.1: структура

div є універсальним контейнером і сам по собі не позначає призначення.
header означає вступну область, nav — навігацію, main — основний вміст,
section — тематичний розділ, article — самостійний матеріал, aside — побічний
пов’язаний вміст, footer — завершальну інформацію. У поточному макеті aside
не потрібний. div залишено для контейнера та сітки: вони керують розташуванням,
а не позначають новий розділ. Джерело: [1].

Мініексперимент для повторення: у DevTools тимчасово замінити загальні
header/main/footer на div, зберігаючи класи. Вигляд може залишитися таким самим,
але стандартні області banner/main/contentinfo більше не задаються цими тегами.
У виконаній перевірці оновленої сторінки браузер розпізнав banner, navigation,
main і contentinfo. Порівняння після заміни тегів студенту слід виконати окремо.

## Дослідження 4.2: заголовки

H1 — «Порівняйте тарифи для роботи з даними».
H2 — «Тарифні плани»; під ним H3 — Basic, Pro, Enterprise.
Другий H2 — «Як відрізняються тарифи»; його H3 пояснюють кожен план.

Рівень заголовка показує місце в структурі, а розмір визначає CSS.
Послідовність H1 → H4 → H2 створила б пропуск рівнів і ускладнила навігацію.
Повернення з H3 до H2 означає початок наступного розділу. Джерело: [2].
Ієрархія поточної сторінки перевірена через DOM браузера.

## Дослідження 4.3: метадані

title називає сторінку у вкладці й може бути джерелом заголовка в пошуку.
description коротко описує вміст і може використовуватися для сніпета.
Google не гарантує дослівне відображення цих значень. Джерела: [3], [4].
charset задає кодування, viewport — поведінку ширини на мобільних пристроях,
robots керує інструкціями для пошукових роботів. Окремий robots тут не потрібний.
keywords не додано. Конкретна назва з Basic, Pro, Enterprise інформативніша за
«Pricing», а опис з цінами й характеристиками — за «Pricing page».

Canonical указує заплановану основну адресу результату:
https://splothy.github.io/lab_WEB/lab3/ . Це не перенаправлення і не підтвердження
деплою. Якщо основний домен зміниться, потрібно оновити canonical. Джерело: [7].

## Дослідження 4.4: контент, посилання, зображення

Тексти пояснюють кількість користувачів, сховище та підтримку без вигаданих
переваг. Explore Basic описує перехід краще, ніж Click here. Усі три CTA мають
справжні локальні цілі. a виконує перехід, button відкриває або закриває
підказку. Не додано оплату чи несправжні контактні адреси. Джерела: [5], [6].

Alt передає зміст зображення, коли його не видно, зокрема користувачам
скринридерів. Для зображення порівняння трьох планів опис «Три тарифні плани:
Basic, Pro та Enterprise» конкретніший за «pricing plans». Опис має відповідати
реальному зображенню та його ролі. Декоративні зображення мають порожній alt.
Повторення ключових слів не замінює корисного опису. У цій реалізації img немає,
тому цей приклад є теоретичним порівнянням, а не тестом зображення сторінки. [8]

## Виконані перевірки

- У браузері перевірено один main, загальні header/nav/footer та заголовки.
- Перевірено description і canonical у DOM.
- Ширини 320, 390, 768, 769 та 1440 px: горизонтального переповнення немає;
  до 768 px — одна колонка, вище — три.
- Перехід Explore Pro змінює hash на #pro-details.
- Кнопка відкриває підказку; кнопка закриття закриває її без JavaScript.
- Зовнішня перевірка W3C Nu не виконана: передавання локального HTML
  заблоковане автоматичною перевіркою дозволів. Локальні перевірки не є
  заміною повної перевірки валідатором HTML.
